# 环境的部署描述

每个环境一个目录,目录里的 `compose.yml` 描述这台机器上跑什么:

- `image:` 指向 CI 推好的不可变标签,**不含 `build:`**
- 端口、卷、主机路径、`env_file` 都在这里(它们是环境的事实,不是代码的属性)
- 密钥不进 git:服务器上的 `.env` 由各服务项目的 `PROD_ENV` 变量推送

发布 = 改这里的一行标签。回滚 = revert 那次提交。`docker compose up -d` 只重建标签
变化的服务,同一文件里的其他服务不受影响。

目录随服务开始推镜像而逐个加入,不预先写没有验证过的描述。

镜像一律写成 `<repo>:<commit sha>@sha256:<digest>`:标签给人读,digest 是契约。
标签是可写的,只有 digest 能保证"下次部署跑的还是同一个东西"。
